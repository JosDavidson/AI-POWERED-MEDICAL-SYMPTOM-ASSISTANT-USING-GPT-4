🏥 Experiment Overview & Clinical Objectives

Course: 24CS2506 - Building Applications using GPT-4 | Experiment No.: 6

Academic Standard

🎯 Aim of the Experiment

To develop an AI-powered medical symptom assistant using GPT-4 that analyzes user-reported symptoms, identifies possible associated conditions, generates relevant clinical follow-up questions, and provides general guidance regarding professional medical attention with rigorous safety guardrails.

📝 Problem Statement

Design and develop an AI-powered medical symptom assistant using GPT-4. The application should collect basic user information and symptoms, analyze the reported symptoms, identify possible conditions, generate follow-up questions, and present the results in a structured format. The system must include appropriate safety instructions and clearly state that the generated output is not a medical diagnosis.

🛡️ Safety & Clinical Principles

  • Informational Only: Communicates diagnostic uncertainty; never issues a definitive prescription.
  • Zero Mobile Data Mode: Built-in local rule-based clinical engine runs 100% offline without network costs.
  • Red-Flag Emergency Interceptor: Immediately escalates severe symptoms (chest pain, dyspnea, cyanosis).
  • Contextual Triangulation: Evaluates age, duration, comorbidities, and medications alongside symptoms.
  • Structured JSON / Markdown Reporting: Clean clinical documentation matching lab requirements.

Table 5: Module Design & Responsibilities

Module Responsibility
Input Module Collects raw patient demographic details, free-text symptoms, and health parameters via interactive Web UI and terminal CLI.
Profile Module Validates, sanitizes, and builds structured patient profile objects with unique Case IDs, timestamps, and age cohorts.
Symptom Module Parses natural language symptom text, normalizes clinical terminology, and maps symptoms to physiological organ systems.
Context Module Calculates patient vulnerability risk scores (1-5) by analyzing comorbidity interactions, age modifiers, and drug allergies.
Prompt Module Synthesizes clinical GPT-4 prompts with system role definitions, strict non-diagnostic guardrails, and JSON response schemas.
Analysis Module Evaluates differential conditions, physiological rationales, and likelihoods via local offline heuristic engine or LLM API.
Question Module Generates targeted clinical follow-up questions to clarify symptom progression, fever peaks, or associated red-flags.
Safety Module Detects emergency red-flag symptoms, determines triage urgency levels (Emergency, Urgent, Routine), and embeds safety disclaimers.
Save Module Serializes, formats, and persists complete clinical analysis reports into structured JSON, Markdown, and printable PDF documents.
Main Module Orchestrates the complete 10-module execution pipeline, managing application state, event handlers, and interface rendering.
